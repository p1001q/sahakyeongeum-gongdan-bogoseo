- 적용 프로젝트: 사학연금 퇴직자 수 변화와 수급자 증감 분석 및 특징 도출

## 1. 먼저 결론: 무엇이 필수이고 무엇이 선택인가

| 작업 | 권장 수준 | 판단 |
|---|---|---|
| 공개자료·논문·선행사례 검토 | 필수, 단 가볍고 목적 있게 | 분석 기준과 해석 근거를 만들기 위해 필요. 논문 자체가 최종 목적은 아님 |
| 데이터 수집·정리·품질검사 | 필수 | 잘못된 기준일·단위·중복을 잡지 못하면 이후 결과가 모두 흔들림 |
| Python 분석 코드 | 사실상 필수 | 반복 계산, 그래프 생성, 재현성을 위해 필요 |
| GUI 프로그램·웹 대시보드 | 선택 | 추진안에 필수라고 적혀 있지 않음. 분석·보고서 완성 후 여력이 있을 때 제작 |
| 분석 보고서 | 사실상 필수 | 추진안이 보고서 품질과 결과 평가를 명시함 |
| 발표용 PPT | 준비 권장, 공식 확인 필요 | 발표 가능성이 높고 결과 확산 목적에 필요하나 공식 제출 형식 확인 필요 |
| 데이터 사전·출처표 | 필수 권장 | 공개·가명·정보공개 자료를 섞을 때 정의와 보안범위를 관리하기 위해 필요 |
| 공단 활용안·KPI | 필수 권장 | 분석을 실제 활용성과로 바꾸는 핵심 부분 |

한 줄로 말하면 다음과 같다.

> **논문을 조금 보고, 데이터를 제대로 정리하고, Python으로 재현 가능한 분석을 만든 뒤, 결과를 보고서와 PPT로 전달하는 프로젝트다. 앱 개발은 선택이다.**

## 2. 추천 프로젝트 단계

### 0단계. 요구사항 확정

- 최종 제출일·중간 점검일 확인
- 보고서 분량·양식 확인
- PPT 발표 여부·발표시간 확인
- 프로그램 또는 대시보드가 필수인지 확인
- 핵심 수급자를 퇴직연금수급자로 좁혀도 되는지 확인

**완료 기준:** 무엇을 언제 어떤 형식으로 제출할지 한 장으로 정리됨.

### 1단계. 배경·선행연구 파악과 데이터 신청

- 추진안과 사학연금 제도·용어 이해
- 공단 통계연보·연차보고서·관련 연구자료 확인
- 관련 논문과 타 연금기관 분석사례 수집
- 고정 이메일 가명데이터 신청
- 정보공개청구와 공개데이터 수집

**완료 기준:** 연구 질문별로 참고할 근거와 필요한 데이터 목록이 정리됨.

### 2단계. 데이터 목록·사전·보안 정리

- 원본 파일과 정제 파일 분리
- 데이터별 기간·기준일·단위·컬럼 확인
- 사람 수와 지급 건수 구분
- 결측·중복·범주 변경 확인
- 가명데이터 저장 위치와 반출조건 기록

**완료 기준:** 팀원 누구든 데이터 사전만 보고 각 컬럼의 의미를 설명할 수 있음.

### 3단계. Python 분석 파이프라인 개발

- 파일 불러오기
- 컬럼명·연도·범주 표준화
- 품질검사 자동화
- 핵심 지표 계산
- 표와 그래프 자동 저장
- 원본을 수정하지 않고 정제 결과를 별도 저장

**완료 기준:** 처음부터 다시 실행해도 같은 표·그래프가 생성됨.

### 4단계. 세 가지 과업 분석

1. 퇴직자 수 변화 분석
2. 수급자 증감 분석
3. 개별·관계 특징 도출

**완료 기준:** 핵심 그래프 6~10개와 근거가 있는 특징 후보가 작성됨.

### 5단계. 결과 검증과 핵심 특징 확정

- 계산을 다른 팀원이 재검산
- 공개자료와 가명·정보공개자료 총계 비교
- 사실·해석·가설을 구분
- 반대 해석과 한계 확인
- 핵심 특징 3~5개 확정

**완료 기준:** 각 특징에 근거표·그래프·한계가 연결됨.

### 6단계. 공단 활용안·KPI 설계

- 어떤 공단 업무와 연결되는지 정리
- 실행 대상·시기·방법 제안
- 성과 확인용 KPI 설정
- 데이터 품질 개선·신규 개방 제안

**완료 기준:** 모든 핵심 특징이 `근거 → 공단 제안 → KPI`로 이어짐.

### 7단계. 보고서 작성

- 분석 전부터 목차와 빈 표를 만들어 병행 작성
- 최종 수치·그래프 삽입
- 공단 활용안과 한계 정리
- 출처·부록·재현절차 정리

**완료 기준:** 보고서만 읽어도 연구 질문·방법·결과·제안을 이해할 수 있음.

### 8단계. PPT·발표 준비

- 보고서 전체를 복사하지 않고 핵심 이야기만 압축
- `왜 중요한가 → 무엇을 봤나 → 무엇을 발견했나 → 공단이 무엇을 할 수 있나` 순서로 구성
- 발표시간에 맞춰 슬라이드 수 조정
- 예상 질문과 답변 준비

**완료 기준:** 제한시간 내 발표가 끝나고 모든 핵심 수치를 설명할 수 있음.

### 9단계. 최종 QA·제출

- 보고서와 PPT 수치 일치 확인
- 그래프 축·단위·기준연도 확인
- 개인정보·희소 셀·가명데이터 반출 여부 확인
- 실행 코드와 환경정보 확인
- 제출 파일명·형식·마감 확인

**완료 기준:** 제출 체크리스트를 두 명 이상이 교차 확인함.

## 3. 논문은 어느 정도 봐야 하나

정식 학술논문처럼 방대한 체계적 문헌고찰을 할 필요는 없다. 대신 **결론을 멋대로 해석하지 않기 위한 최소 선행연구 검토**는 필요하다.

### 권장 분량

- 공단·정부 공식자료 3~5개
- 관련 학술논문 3~5개
- 타 연금기관 또는 공공데이터 활용사례 2~3개

중복을 제외하고 실제 보고서에 쓸 만한 자료 약 8~12개면 시작 단계에는 충분하다.

### 찾아볼 주제

1. 사학연금 제도와 퇴직급여·퇴직연금 구조
2. 사립학교 교직원 퇴직·고령화 관련 연구
3. 공적연금 수급자 증가와 재정·서비스 수요
4. 연금선택과 지급개시연령 관련 연구
5. 퇴직자·연금수급자 시계열 분석 사례
6. 공공데이터 활용 우수사례와 데이터 품질 개선 사례

### 논문 한 편당 기록할 것

- 서지정보와 링크
- 연구 질문
- 사용 데이터와 기간
- 핵심 결과 3줄
- 우리 연구에 쓸 부분
- 그대로 적용할 수 없는 차이·한계
- 보고서에 인용할 위치

논문을 많이 읽는 것보다 **우리 분석의 정의·해석·제안에 실제로 쓰이는 자료를 남기는 것**이 중요하다.

## 4. Python은 프로그램보다 분석 파이프라인이 먼저

현재 반드시 필요한 것은 사용자가 버튼을 누르는 완성형 앱이 아니라, 데이터를 반복해서 처리할 수 있는 **재현 가능한 분석 프로그램**이다.

### 권장 기능

1. 공개데이터·정보공개자료 불러오기
2. 컬럼명·연도·학교급·직종 표준화
3. 중복·결측·합계 불일치 검사
4. 퇴직자 증감 지표 계산
5. 수급자 순증 지표 계산
6. 집단별 구성비·기여도 계산
7. 시차 비교
8. 보고서용 표·그래프 자동 저장

### 권장 폴더 구조

```text
data/
  raw_public/       공개데이터 원본
  raw_restricted/   가명데이터 원본, 보안조건 확인 후 사용
  processed/        정제 데이터
notebooks/          탐색·분석 노트북
src/                불러오기·정제·지표·시각화 함수
outputs/
  figures/          보고서·PPT용 그래프
  tables/           최종 표
docs/               데이터 사전·보고서·PPT 기획
```

### 개발 순서

`불러오기 → 품질검사 → 정제 → 지표계산 → 그래프 → 결과 저장`

Streamlit 같은 대시보드는 이 전체 과정이 안정된 뒤 같은 계산 코드를 재사용해 만드는 선택 산출물로 둔다.

## 7. 홈 화면 오른쪽 빈 카드에 넣을 추천 내용

스크린샷의 오른쪽 빈 카드에는 `🚦현재 진행 상황`을 넣는 것이 가장 유용하다.

```text
🚦 현재 진행 상황

현재 단계: 착수·데이터 신청
이번 주 목표: 신청 완료 + 공개데이터 수집

다음 할 일
1. 가명데이터 이메일 제출
2. 정보공개청구 제출
3. 공개데이터 원본 다운로드

확인 필요
- 최종 제출일
- PPT 발표시간
- 프로그램 개발 필수 여부
```

홈에서는 세부 내용을 전부 보여주지 말고 `현재 단계`, `이번 주 목표`, `다음 할 일 3개`, `막힌 것`만 보여준다.

## 8. 3인 팀 권장 역할

| 역할 | 1차 책임 |
|---|---|
| A. 데이터·코드 | 데이터 수집·사전·정제·품질검사·Python 파이프라인 |
| B. 분석·시각화 | 퇴직자·수급자 분석, 통계지표, 그래프, 결과 검산 |
| C. 문헌·정책·문서 | 논문·공식자료, 특징 종합, 공단 활용안, 보고서·PPT 관리 |

역할을 완전히 분리하지 않고 핵심 수치와 결론은 작성자 외 한 명이 반드시 검산한다.

## 9. 산출물 연결관계

```text
논문·공식자료 ─────────────┐
                            ↓
데이터 신청·수집 → Python 정제·분석 → 그래프·표 → 핵심 특징 → 공단 제안·KPI
                                                    ↓
                                               분석 보고서
                                                    ↓
                                               발표용 PPT
```

보고서와 PPT는 분석이 끝난 뒤 갑자기 만드는 별도 작업이 아니다. 문헌·데이터·그래프·특징을 노션에서 계속 연결해두고, 보고서는 이를 자세히 설명하며 PPT는 핵심만 압축한다.

## 10. 당장 만들 페이지 우선순위
