## 1. 사용자 사고 흐름에 대한 판단

### 결론

방향은 타당하다. 특히 `기존 공개데이터 활용 → 분석 중 발생한 질문 → 현재 데이터로 답할 수 없는 이유 → 필요한 신규 공공데이터 → 공개 후 가능한 연구와 공단 활용`이라는 흐름은 공공기관의 데이터 개방 개선 과제로 적합하다.

이 흐름은 추진계획안에 명시된 다음 구조와도 직접 맞닿아 있다.

- 연구 결과를 활용한 공단 제도 개선 및 정책 아이디어 발굴
- 데이터 개방 → 연구 활용 → 성과 창출 → 재개방의 선순환
- 우수 연구 결과에 대한 공공데이터 신규 개발 추진
- 데이터 품질 개선과 활용도 향상

따라서 마감 직전에 억지로 만든 방향이 아니라, 공단이 애초에 기대한 성과 유형 중 하나로 볼 수 있다.

### 잘 잡은 부분

1. 새 프로그램을 무리하게 만들기보다 현재 역량과 시간 안에서 공단에 남길 수 있는 결과를 찾았다.
2. 기존 공개데이터를 실제로 사용한 뒤 추가로 필요한 데이터를 제안하려 했다.
3. 신규 데이터가 공개되면 가능한 연구와 기대효과까지 연결하려 했다.
4. 보고서를 `문제 지적 → 개선 → 개선 후 활용`의 흐름으로 만들려 했다.
5. 담당자의 조언을 팀원들과 공유하고 분석 대상을 빠르게 구체화했다.

### 회사 제출물에 맞게 고칠 부분

1. **비판 중심 표현을 개선 중심 표현으로 바꾼다.**  
   `공개데이터가 엉망이다`가 아니라 `현재 개방자료는 현황 파악에는 유용하지만 이용자 경험을 진단할 세부 통계가 부족하다`고 쓴다.

2. **데이터가 없다는 사실과 실제 문제가 있다는 주장을 구분한다.**  
   현재는 고령 수급자의 인증 실패나 불편을 확인한 것이 아니다. 이를 확인할 통계가 없다는 것이 확인된 사실이다.

3. **한계를 많이 나열하는 것보다 중요한 공백을 우선순위화한다.**  
   파일 형식, 컬럼명, 기준일, 연령대 부재를 모두 적을 수 있지만 최종 결론은 `연령대·채널·인증단계별 이용통계 부재`에 집중한다.

4. **새 데이터를 요청하는 데서 끝내지 않는다.**  
   데이터명, 집계단위, 컬럼, 주기, 보호조치, 분석지표, 공단 행동과 KPI까지 설계한다.

5. **기존 분석은 신규 제안의 근거가 되어야 한다.**  
   그래프를 많이 만드는 것이 목적이 아니라 수급자 규모 변화와 서비스 관리 필요성을 설명할 최소 증거를 만드는 것이 목적이다.

## 2. 최종 사고 구조

회사 보고서에서는 다음 여섯 문장으로 논리를 고정한다.

1. 공단의 공개데이터를 이용해 퇴직자와 퇴직연금수급자, 평균연금액의 장기 변화를 분석했다.
2. 분석 결과는 수급자 규모와 관련 서비스 수요가 장기적으로 어떻게 변해왔는지 보여준다.
3. 다음 단계로 이용자가 온라인 서비스에 원활하게 접근하는지 확인할 필요가 있다.
4. 현재 개방자료에는 연령대·채널·인증단계별 이용통계가 없어 이 질문을 검증할 수 없다.
5. 이에 공단이 개방할 신규 통계의 구조와 보호조치, 활용지표를 제안한다.
6. 공단은 제안 데이터를 활용해 인증·화면·상담 지원의 개선 우선순위를 정하고 개선 효과를 추적할 수 있다.

## 3. `추진계획안.pdf`의 시각 형식 분석

### 문서 성격에 대한 주의

`추진계획안.pdf`는 연구보고서 제출용 빈 양식이 아니라 공단 내부 추진계획 문서다. 따라서 목차와 문장을 그대로 복제할 필요는 없다. 대신 공단이 익숙하게 보는 시각 체계를 연구보고서에 적용한다.

### 표지

- A4 세로형
- 상단 오른쪽 TP 로고
- 제목 위·아래에 파란색 계열의 굵은 가로 띠
- 중앙 정렬된 굵은 보고서 제목
- 하단 중앙에 작성연월과 팀명
- 배경은 흰색으로 유지하고 장식을 최소화

### 본문 대제목

- `Ⅰ. 연구개요`처럼 로마숫자와 장 제목 사용
- 흰색 글자를 어두운 남색·회청색 가로 띠 위에 배치
- 띠는 본문 폭 전체 또는 대부분을 차지
- 장이 바뀔 때 같은 규격을 반복

### 중제목

- 검은색 정사각형 안의 흰색 번호와 굵은 제목을 한 줄에 배치
- 제목 위·아래에 가는 회색 선 사용 가능
- 예: `1 분석 개요`, `2 신규 개방안`, `3 활용방안`

### 내용 계층

- 1단계 항목: `□` + 굵은 소제목
- 2단계 설명: `○` + 문장
- 3단계 보충: `-` + 짧은 세부 설명
- 주의·출처·예외: `※`
- 굵은 글씨는 핵심어와 결론에 제한적으로 사용

### 표

- 제목행은 연한 보라·회색 계열 채움
- 얇은 회색 테두리와 충분한 셀 여백
- 숫자는 오른쪽, 연도·범주는 가운데, 설명은 왼쪽 정렬
- 단위와 출처는 표 바로 위 또는 아래에 표시

### 머리말·꼬리말

- 본문 페이지 하단 중앙에 `- 1 -` 형식의 페이지 번호
- 오른쪽 하단에는 보고서명 축약 또는 팀명·작성연월을 작게 표시 가능
- 원본 스캔의 출력시각·사용자번호는 보고서에 복제하지 않는다.

### 권장 글꼴과 색상

- 본문: 나눔고딕 또는 Noto Sans KR 10.5~11pt
- 장 제목: 같은 글꼴 Bold 16~18pt
- 중제목: Bold 13~14pt
- 표·주석: 9~10pt
- 주색: 짙은 남색 `#24364B`
- 보조색: 공단 청색 `#138ACB`
- 연한 표 채움: `#E7E4ED`
- 본문 글자: `#222222`

Word와 PDF 변환 환경에서 글꼴이 달라질 수 있으므로 최종 PDF에서 한글 누락과 줄바꿈을 반드시 확인한다.

## 5. 회사 보고서답게 만드는 작성 원칙

1. 첫 1~2쪽에서 문제·핵심 결과·제안을 모두 파악할 수 있게 한다.
2. 각 장의 첫 문장은 결론으로 시작하고 뒤에 근거를 붙인다.
3. 그래프마다 `그래서 공단에 어떤 의미인가`를 한 문장으로 쓴다.
4. 제안은 중요도·실현가능성에 따라 1단계, 2단계로 나눈다.
5. 공개데이터 한계는 책임 추궁이 아니라 개선 가능한 업무 요건으로 표현한다.
6. 모든 수치에는 기준연도·단위·출처를 표시한다.
7. 요약문과 결론의 제안 문구가 서로 일치해야 한다.

## 6. 권장 신규 개방 우선순위

### 1단계: 담당자가 직접 제시한 최소 통계

- 연도·연령대별 PC/모바일 접속 건수
- 연도·연령대별 인증방법별 건수
- 연도·연령대별 인증성공·실패 건수
- 연도·연령대별 비밀번호 분실 인증 알림톡 발송 건수

### 2단계: 분석 활용도를 높이는 확장 통계

- 서비스 업무유형
- 업무완료 여부
- 실패사유 범주
- 관련 상담·문의 건수

1단계는 현재 시스템에서 비교적 단순 집계가 가능한지 우선 검토하고, 2단계는 내부 데이터 연결성과 보안성을 확인한 뒤 확장하는 구조로 제안한다.
