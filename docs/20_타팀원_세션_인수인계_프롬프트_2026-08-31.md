## 2. 분업 방식 — 파일 선점 방식

이름으로 미리 정해두지 않고, **먼저 `git pull`한 뒤 `output/report_packages/` 안에 아직 없는 파일 중 docs/18 §8 순서상 가장 앞선 것**을 고른다.

남은 순서(2026-08-31 기준): `07_공단활용_로드맵_KPI_패키지.md` → `01_연구개요_패키지.md` → `02_공공데이터_활용및검증방법_패키지.md` → `08_결론_패키지.md` → `00_요약문_패키지.md` → `99_전문보고서AI_통합전달본.md`

- `07`(Ⅶ장)과 `02`(Ⅱ장)는 서로 다른 내용이라 두 사람이 동시에 시작해도 충돌 없음 — 이 둘을 먼저 병렬로 진행하는 걸 권장한다.
- `01`(Ⅰ장), `08`(결론), `00`(요약문)은 `07`이 끝난 뒤 시작한다(내용이 Ⅶ장 결론에 의존).
- `99`(통합 전달본)는 위 전부가 끝난 뒤 **마지막에 한 사람만** 만든다. 두 사람이 동시에 만들면 충돌한다.
- 작업 시작 직전에 반드시 `git pull`로 다시 확인 — 그 사이 다른 사람이 그 장을 이미 시작했을 수 있다.
- 한 장을 다 쓰면 그 장 파일만 커밋하고 바로 `git push`한다. 완료 전 상태를 오래 로컬에 묵히지 않는다.

제목·목차·논리 흐름·연구 방향은 이미 확정됐다. 다시 브레인스토밍하거나 승인받으려고 멈추지 마라. 가명데이터·가상값·추정값을 쓰지 말고, 결과를 근본적으로 바꾸거나 실제 작업을 막는 문제만 질문해라.

**작업 순서**: `git pull`로 최신 상태를 받은 뒤, `output/report_packages/` 안에 아직 없는 파일 중 다음 순서에서 가장 앞선 것을 고른다 — `07_공단활용_로드맵_KPI_패키지.md` → `01_연구개요_패키지.md` → `02_공공데이터_활용및검증방법_패키지.md` → `08_결론_패키지.md` → `00_요약문_패키지.md` → `99_전문보고서AI_통합전달본.md`. `07`과 `02`는 병렬 진행 가능하니 둘 중 하나를 고르고, 다른 사람이 이미 시작한 파일(이미 존재하는 파일)은 건드리지 않는다. `99`는 나머지 전부가 끝난 뒤 마지막에 한 사람만 만든다.

고른 장은 `docs/18`의 9개 블록(장 역할·앞뒤 연결·세부 논증 지도·본문 원고·팩트시트·시각자료 삽입표·사실/해석/가설/제안 구분·허용/금지 주장·자체 검수표)을 전부 포함해서 작성한다. 수치는 반드시 `data/raw/`, `data/processed/`, `output/evidence/`의 원본·재현 산출물로 역추적 가능해야 하며, 필요하면 `scripts/`의 기존 코드를 재실행해서 재검산한다. 새 그래프가 필요하면 `output/figures/verified/`에 이미 검증된 것을 우선 재사용하고, `output/figures/team_candidates/`는 본문에 쓰지 않는다.

작성이 끝나면:

1. `python3 scripts/verify_workspace.py`를 실행해 `판정: 정상`을 확인한다.
2. `PROJECT_CONTEXT.md` 맨 아래에 새 번호 섹션을 추가해 무엇을 완료했는지 기록한다(기존 섹션은 건드리지 않는다).
3. 그 장 파일만 커밋하고 `git push`한다. 커밋 메시지에 어떤 장을 완성했는지 한국어로 쓴다.
4. 이 세션에서는 DOCX·PDF·PPT·앱·대시보드를 만들지 않는다.

작업 시작 시 현재 어떤 장을 고를지와 이유를 3줄 이내로 알린 뒤 바로 실행해라.
